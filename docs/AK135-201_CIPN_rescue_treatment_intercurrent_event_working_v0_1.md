# AK135-201 CIPN挽救治疗对EOT双主要终点的影响：直接同类研究与统计建议 v0.1

**审阅日期：** 2026-10-13  
**状态：2026-10-13用户表示“我作为统计师同意”Treatment Policy的统计原则；同时指出“如果挽救治疗本身就导致EOT呢？” 因此该原则获统计侧认可，但提前EOT与挽救起始的评价时序、挽救/停药因果区分尚待明确。本稿继续作为实施前待确认工作稿，原方案Word不改。**

## 1. 明确来自AK135-201原始方案的事实

核对上传原始`AK135-201方案 v0.1.docx`正文§5.8.3“挽救治疗”（段落492–502）以及§5.8.1“禁止或限制使用的合并用药或治疗”（段落467–475）：

- 平时原则上禁止以预防或治疗CIPN为目的使用影响有效性评价的药物/非药物治疗，但**当出现新发或加重CIPN且临床需要时，研究者可决定挽救治疗**，包括原§5.8.1限制的干预。
- **临床允许时尽可能在首次挽救治疗前完成CTCAE、PRO等CIPN评价。**
- 记录救治原因、CIPN症状/等级、救治开始/结束日期、具体药品/非药物措施与剂量/用法、救治前后症状及是否致背景神经毒性化疗减量/延期/暂停/永久停药。
- **挽救治疗本身不使患者自动停止试验药或退出研究，仍应继续方案有效性/安全性评价。**
- **原方案没有明确规定：若EOT评估在挽救治疗之后，是否使用EOT实测结果作双主要终点、是否用挽救前评估替代EOT、是否当作失败。** 这是本轮统计要定的一项intercurrent event原则，不能从§5.8.3“允许继续评价”直接推断为已确认的Treatment Policy。

## 2. 一手同类型试验与方法学证据

### POLAR-A/M，PledOx + mFOLFOX6预防CIPN

- [POLAR-A Phase III Protocol v8.0（NCT04034355）](https://cdn.clinicaltrials.gov/large-docs/55/NCT04034355/Prot_000.pdf) §7.6（Protocol印刷56页/PDF第57页）：**允许**NSAIDs/阿片类及其他为神经病理性疼痛使用的药物进行症状治疗；抗抑郁药、抗癫痫药、局麻药不得**预防性**用于神经痛，但可由研究者为实际症状使用；要求记录并存用药名称、开始/结束日期、剂量；其他救治可由研究者酌情给予。§8.1.1.1规定在计划治疗及评估访视继续收集FACT/GOG-NTX。
- [POLAR-A/M SAP v1.0（NCT04034355）](https://cdn.clinicaltrials.gov/large-docs/55/NCT04034355/SAP_001.pdf)：此次针对“rescue”、救治后计分的检索**未找到**专门“救治后全部纳入主要”或“救治后删失/替代”的明确句子。**严禁将本试验说成明确采用Treatment Policy或把救治视失败的证明。**
- 适用启示：在直接相似CIPN预防RCT中，**允许临床救治与详细记录**已具有可操作的真实先例；救治后疗效的估计目标和使用数据规则应在本研究先写清楚。

### Alliance A221805，度洛西汀3臂Ⅱ期预防奥沙利铂CIPN

- [Alliance A221805 Protocol Update05，2024-01-11（NCT04137107）](https://cdn.clinicaltrials.gov/large-docs/07/NCT04137107/Prot_SAP_000.pdf) §8.1：允许其他CIPN镇痛药，但因研究药自身就是度洛西汀，对抗抑郁药和抗惊厥药存在**更严格**限制；每周期、随访收集合并药；结束研究药后，若疼痛性CIPN确有临床需要，可能使用度洛西汀，必须记录。这一限制是药品相关，不应原封不动套用于AK135。
- 同文件§13.5主分析基于可评价的19–21周症状问卷；此次核对未发现单独的“使用救治后把患者剔除”或“救治即主终点失败”的普遍规则；**不把找不到视为证明一定纳入**。
- [已发表Ⅱ期结果](https://pubmed.ncbi.nlm.nih.gov/42052361/)证实三臂、主要PRO响应、可评价人数143/199(71.8%)，但是**不能据此推出它采用哪一种rescue estimand**。

### ACTTION-CONCEPPT针对CIPN预防RCT设计的专家共识

- [2018 Neurology原始共识（PMID30054438）](https://pubmed.ncbi.nlm.nih.gov/30054438/)；[全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC6133627/) **Concomitant medications**：药物可能掩盖CIPN相关疼痛或影响试验终点；一概禁止镇痛药可能造成伦理与招募/推广问题；允许时应重视用药稳定性和日志。共识支持**记录并考虑救治干扰**，不是直接指定AK135-201的estimand。

### 方法学依据：ICH E9(R1)，不是CIPN试验先例

- [ICH E9(R1) Step4 2019 §A.3.2](https://database.ich.org/sites/default/files/E9-R1_Step4_Guideline_2019_1203.pdf)：**Treatment Policy Strategy**对新增/救治用药这一intercurrent event，仍使用发生该事件后实际测得的结局；与hypothetical、composite、while-on-treatment属于不同科学问题。该规范**允许但不强制**选择某一策略；研究应据要回答的科学问题预先约定。
- 本项目已定为**EOT当次**的CIPN20 18-item较基线增加≥10及CTCAE感觉/运动≥2；**不是从C1D1至EOT任何一次“ever”达到阈值**。因此不能因为挽救前曾≥2级而在主EOT分析强制记为有事件。

## 3. 三种可能规则与统计含义

| 策略 | 对于已挽救且EOT有实测的受试者 | 与已确认EOT双主要的关系 | 风险 |
|---|---|---|---|
| **A—Treatment Policy（推荐）** | **继续使用挽救后实际EOT的CIPN20/CTCAE**，按各自同一阈值判定；同时单独描述挽救治疗情况 | **不变更终点定义、不加“曾发生”规则、无额外访视**；回答随机分配AK135/安慰剂加允许常规症状救治条件下的EOT表现 | 救治可能减轻症状，特别影响PRO；不代表“完全不使用挽救药情况下的AK135纯生物预防效应”，组间不同救治比例可稀释/复杂化差异 |
| B—Composite | 挽救治疗本身直接算主要结局恶化（例如任何挽救=事件） | **修改已确认的两个二分类主要终点**，挽救指征、措施与CIPN20≥10/CTCAE≥2的严重度阈值可能不一致 | 把仅因轻度痛而适当治疗或因不同临床决策而救治的病例强制变为事件，且需重新对阶段1 CP设计假设适用性评价 |
| C—Hypothetical/while-before-rescue | 挽救后EOT不纳入，尝试预测无救治下EOT或用挽救前近时点代替 | **挽救前测量未必是EOT**，会变更科学问题和估计策略 | 救治为症状恶化后的非随机事件，简单排除救治者/LOCF/前一次替代EOT可严重信息性选择偏倚；需要额外模型假设，不适合目前简洁II期 |

**示例（仅说明统计规则）：** 某患者C3出现CTCAE 2级开始治疗，EOT实际CTCAE 1级，则A规则下EOT CTCAE≥2主要终点**为0**（非事件），而非按C3记录自动判1；若EOT问卷较基线恶化为12分，则**CIPN20主要终点为1**。挽救情况单独汇总。若EOT缺失，则仍按现有CP-07 missing/indeterminate规则，不因发生挽救治疗就默认补0或补1。

## 4. 统计建议：拟写入方案的简洁文字（待用户确认）

> **CIPN挽救治疗对主要有效性评价的影响**
>
> 对于研究期间因CIPN接受挽救治疗的试验参与者，仍按方案规定完成后续CIPN评价。两项EOT主要有效性终点均采用Treatment Policy Strategy，即无论EOT前是否接受挽救治疗，均以EOT访视实际取得的QLQ-CIPN20和CTCAE评价结果进行判定；接受挽救治疗本身不作为主要终点事件，也不导致受试者被排除或将EOT结果判为缺失。
>
> 对挽救治疗使用情况及开始时间按随机治疗组进行描述性汇总，以辅助解释主要终点结果。挽救治疗前完成的CIPN评价用于病程和支持性描述，不替代预定EOT访视结果。EOT结果缺失时仍按研究已有缺失数据规则处理。

**可简化的统计实现：** 在既定的挽救治疗资料采集项目中，记录EOT前是否接受挽救、首次救治日期、类型/持续时间及救治前症状/CTCAE。报告各组被救治n/N、首次救治的时点、必要时对应CIPN状态；无正式挽救发生率假设检验/新增复合主要终点；不强制额外挽救前非计划访视。**不做“仅无救治受试者”作为主要疗效估计**。

## 6. 新情况：CIPN挽救治疗与提前EOT同日/同原因发生（2026-10-13）

**用户原话：**“我作为统计师同意，但是如果说挽救治疗本身就导致EOT呢？”

### 6.1 原始AK135-201 CP v0.1原文已明确的区别（本段基于上传原始Word逐段核对）

1. **§5.8.3**（原Word段落493–502）：出现新的或加重CIPN、医学认为有必要时可以给予挽救治疗；若临床允许，**尽可能在首次救治前完成CTCAE与PRO**；须记录挽救原因、严重度、时间、措施、是否导致背景神经毒性化疗剂量调整/延迟/暂停/永久停药；**“接受挽救治疗本身不意味着试验参与者必须停止试验治疗或退出研究”**，除非安全性或其他方案原因使其终止治疗。
2. **§5.2给药**（段落416）规定：神经毒性抗肿瘤药物延迟或暂停，AK135同步延迟或暂停；**神经毒性药物提前永久终止，AK135同步永久停止**。§4.6.1段落373–385规定治疗停止的临床原因，与是否接受挽救为不同概念。
3. **§6治疗期/§7有效性评价**（原Word段落527、529、548、563、575、599）：因任何原因永久提前停试验治疗，**决定停药后的3天内**完成提前终止/EOT相关CIPN评价；计划末周期与提前永久终止访视并非共同固定时间点。

### 6.2 必须区分的情景

| 情景 | 是否触发提前EOT | 主要终点处理 |
|---|---|---|
| 仅开始CIPN挽救，神经毒性化疗和AK135继续 | **否**，§5.8.3明确不能单凭救治自动停试验药 | 后续真实EOT的CIPN20/CTCAE照常纳入（Treatment Policy） |
| CIPN严重恶化导致神经毒性化疗及AK135永久停用，同时/随后开始挽救 | **是，因永久停试验治疗而提前EOT**，不是“救治药本身触发EOT” | 在停药决定后3天内完成提前EOT评估；**临床允许时尽量在首次救治前完成与提前EOT相符的正式测量**，不为测量延误必要救治；若EOT在救治后，不能凭救治前临时测量自动替代正式EOT |
| 因肿瘤进展、其他毒性或个人意愿等原因提前停试验治疗，同时接受CIPN救治 | **是，因停止试验治疗** | 按实际提前EOT；不能自动说“CIPN导致EOT”，必须记录停药原因 |
| 救治后完成EOT评价，测得症状改善（例如救治前CTCAE G2、EOT G1） | 视是否实际停试验治疗而定 | 已确认的主要定义为**EOT当次状态**，故CTCAE主要按G1判**0**，但另汇总救治前G2和CIPN相关提前永久停药；**不得临时改为ever G2或依据停药强制将两个主要终点判1** |
| 因CIPN停药但没有有效EOT测量 | 提前EOT应执行但资料缺失 | 仍按原已定missing/indeterminate，不可擅自判0；临床已知G2或救治事实作为支持性临床信息，不自动充当EOT双主要结果 |

### 6.3 统计建议：保持既有EOT主定义，增加简短防混淆原则

**先明确estimand边界：** Treatment Policy仅说明**“是否受CIPN挽救治疗”**这个intercurrent event之后仍采用实际可观察的EOT；**提前终止试验治疗改变EOT测量时点**是另一层处理。项目既有规则为“终止治疗即提前EOT”，因此两者组合适用，而不是说“只要开始救治就必须提前EOT”。

**研究方案建议补写一句：** “接受CIPN挽救治疗本身不触发EOT。若因CIPN相关不良反应或其他规定原因提前永久停止试验治疗，应按方案完成提前终止/EOT评价；在不影响必要治疗的前提下，尽可能在首次挽救治疗前完成该评价。实际EOT时取得的两项主要终点评分按预定规则判定；不能完成EOT者按照缺失数据处理规则执行。”

**支持性呈现（建议常规描述）：** 按随机组记录及汇总（i）任何挽救使用；（ii）**因CIPN导致神经毒性化疗/试验治疗提前永久终止**；（iii）救治前最近一次可用CIPN症状/CTCAE等级及提前EOT实际评分，显示可能的症状遮蔽与选择性提早EOT。可以基于§5.8.3已有记录，不必添加新的正式主要复合终点或假设检验。

**如需更强稳健性：** 若出现大量“CIPN恶化→救治+停药→EOT迅速减轻”的案例，可在SAP预设支持性**composite sensitivity analysis**，例如将**因CIPN直接导致提前永久停试验治疗**归为不利状态（两量表分别合理实施，不把不相干的救治自动判CIPN20≥10）。这种规则一旦影响阶段1 CP将需重新评估其适用性，**目前未建议改主分析，不应未经用户/医学确认自动新增**。

**待用户决策的真正问题：** 是否接受方案层面“**救治本身不触发EOT；若同时因CIPN提前永久停治疗，正式提前EOT按停药后3天内开展，临床允许时先测量再救治；若先救治则仍使用实际EOT评分并作支持性记录**”这条精简规则？这与上一轮用户统计同意的Treatment Policy是兼容的。**不得把‘挽救就产生EOT’作为原Word已规定规则。**

**原方案Word冻结不变。**
